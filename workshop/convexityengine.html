ConvexityEngine

market infrastructure · running

A live monitoring engine for a personal trading practice: webhook ingestion from charting alerts, a state registry that tracks instruments through their regimes, snapshot logging, and an alerting layer — Postgres and serverless functions, wired to run unattended.

How it is put together

The system is a pipeline with four separable stages, and the separation is the point. Charting alerts arrive at a webhook endpoint as they fire. That endpoint's only job is to accept the message, validate it, and write it down — it makes no decisions, because an endpoint that decides is an endpoint that can be wrong in ways you cannot reconstruct later.

Behind it, a state registry holds the current picture: which instruments are being watched, and what regime each is understood to be in. This is the system of record. Alerts move instruments between states; the registry is what anything downstream reads.

Alongside the registry, snapshots accumulate — a log of what the system believed and when it believed it. A live state table answers "what is true now"; the snapshot history answers "what did this look like on the day, and why did it act the way it did." The second question is the one worth being able to answer, and it can only be answered if you were writing it down before you needed it.

The alerting layer sits at the end, reading state and reaching the operator when something warrants attention.

Why it runs unattended

Because markets do not wait for the operator to be at a desk, and because a monitor that needs babysitting is a second job rather than a tool. Serverless functions mean there is no machine to keep alive, no process to restart, and nothing that quietly dies at three in the morning and is discovered at nine. Postgres holds the state so that the compute can be stateless and disposable: any invocation can fail and be retried without the system losing its place.

What it deliberately does not do

It does not execute. It does not size. It holds no view about what should be bought or sold — that judgment stays with the operator, and the reasoning behind it stays private. The engine's remit is narrow on purpose: watch, record, and say something when a watched thing changes. A narrow remit is why the architecture can be described in public at all.

The engineering is described here; the strategy it serves is not, by design.
